🛡️ Güvenlik Sertleştirme & NEC CCIS Protokol Gateway

AiPBX; kurumsal VoIP ağlarının karşılaştığı SIP brute-force saldırılarını, yetkisiz çağrı başlatma girişimlerini ve dinleme tehditlerini bertaraf eden çok katmanlı savunma mekanizmalarına sahiptir. Ayrıca tescilli NEC UNIVERGE CCIS protokolünü modern IP dünyasıyla birleştiren kurumsal ağ geçidi mimarisi sunar.

1. Çok Katmanlı Savunma Mimarisi (Defense-in-Depth)

AiPBX sisteminde güvenlik tek bir bileşene emanet edilmez; ağ, taşıma, uygulama ve veritabanı katmanlarında ayrı ayrı sertleştirme uygulanır:

Katman Uygulanan Güvenlik Politikası Sağlanan Koruma
Ağ Katmanı (L4) Nginx L4 Stream + ALPN Filtreleme Dışarıya açık port sayısını asgariye indirir. Rastgele port taramalarını boşa çıkarır.
Taşıma Katmanı (TLS/SRTP) TLS 1.3, DTLS-SRTP, SDES-SRTP, TURNS Ağ üzerindeki paket yakalama (Sniffing, Wireshark) saldırılarında sesin ve şifrelerin dinlenmesini önler.
Giriş & Hız Sınırı Fail2ban PBX Jails + Nginx Rate Limiting Saniyede onlarca kez şifre deneyen botnet ve SIP tarayıcılarını (friendly-scanner, sipvicious) anında banlar.
Veritabanı Katmanı İki Kademeli Ayrıcalık (Least Privilege) Web arayüzünde olası bir açık durumunda dahi veritabanı tablolarının silinmesini (DROP) engeller.

2. Fail2ban PBX Jails & Otomatik Engelleme

Sistemde Asterisk PJSIP, Apache web sunucusu ve SSH için önceden yapılandırılmış özel Fail2ban kuralları aktiftir:

/etc/fail2ban/jail.d/asterisk.conf 
[asterisk-pjsip]
enabled  = true
filter   = asterisk-pjsip
action   = iptables-allports[name=ASTERISK, protocol=all]
logpath  = /var/log/asterisk/messages
maxretry = 5
findtime = 600
bantime  = 86400

[aipbx-web-auth]
enabled  = true
filter   = aipbx-web
action   = iptables-multiport[name=AIPBX-WEB, port="http,https,8443"]
logpath  = /var/log/aipbx/audit.log
maxretry = 4
findtime = 300
bantime  = 43200
⚡
Akıllı Beyaz Liste (Whitelist): Kurumsal merkez IP'leri, VPN ağ geçitleri ve SIP operatör trunk adresleri otomatik olarak beyaz listeye alınır; böylece personelin yanlış şifre girmesi durumunda şirketin genel IP'sinin engellenmesi önlenir.

3. NEC UNIVERGE CCIS Protokolü ve Gateway (ccisgw) Rehberi

CCIS (Common Channel Interoffice Signaling); NEC tarafından kurumsal santral ağlarında (SV8100, SV8300, SV8500, NEAX) santraller arası özellik şeffaflığı (feature transparency) sağlamak amacıyla ITU-T SS7 No.7 / ISUP ve ITU-T Q.931 (ISDN DSS1) standartları harmanlanarak geliştirilmiş özel bir hibrit protokoldür.

3.1. Ağ Topolojisi ve Temel Kavramlar:

NEC CCIS Sinyalleşme ve Ses Yolu Mimarisi 
+-----------------------------------+                     +-----------------------------------+
|      NEC PBX (Node A / OPC)       |                     |      NEC PBX (Node B / DPC)       |
|                                   |                     |                                   |
|  [Ses Kanalı 1 (B1)] ===========> | === Ses Yolu =====> | ====> [Ses Kanalı 1 (B1)]         |
|  [Ses Kanalı 2 (B2)] ===========> |    (TDM / RTP)      | ====> [Ses Kanalı 2 (B2)]         |
|  [Ses Kanalı N (Bn)] ===========> |                     | ====> [Ses Kanalı N (Bn)]         |
|                                   |                     |                                   |
|  [Ortak Sinyal Kanalı (CCH)] <--> | <-- CCIS-MSU Link-> | <---> [Ortak Sinyal Kanalı (CCH)] |
|                                   |    (HDLC / TCP/IP)  |                                   |
+-----------------------------------+                     +-----------------------------------+
  • Signaling Point (SP): Ağdaki her bir santral bağımsız bir sinyalleşme noktasıdır.
  • Point Code (PC / FPC): Santralin benzersiz kurumsal kimlik numarasıdır (Originating Point Code - OPC, Destination Point Code - DPC, Fusion Point Code - FPC: 1 - 253).
  • Common Channel (CCH / FCCH): Ses kanallarından bağımsız ayrılmış ortak sinyalleşme kanalıdır (TDM'de Kanal 16, IP'de TCP soketi).
  • CIC (Circuit Identification Code): Sinyalin hangi ses kanalına (B-kanal veya RTP) ait olduğunu belirten 12-bit / 16-bit devre kodudur.

3.2. Katman 2 (Data Link) Çerçeveleme:

Katman 2 seviyesinde bağlantı bütünlüğü özel HDLC çerçeveleme ile denetlenir:

  • Frame Delimiter: Başlangıç ve bitiş baytı (0x7E veya NEC özel L2 belirteci).
  • Length Indicator (LI): Takip eden paketin bayt uzunluğu.
  • Sequence Numbers: İleri ve geri sıra numaraları (FSN / BSN) ile kayıpsız teslimat.
  • L2 Checksum: Çerçeve bütünlük doğrulaması.

3.3. Katman 3 Sinyalleşme Birimi (CCIS-MSU Header):

CCIS-MSU (Message Signaling Unit) Paket Formatı 
Byte 0        Byte 1        Byte 2        Byte 3        Byte 4        Byte 5..N
+-------------+-------------+-------------+-------------+-------------+---------------+
|     SIO     |     DPC     |     OPC     |     CIC     |  Msg Type   | Parametreler  |
|  (Sub-Srv)  | (Hedef PC)  | (Kaynak PC) | (Devre Kodu)| (CSTS Kodu) | (Caller/Called|
+-------------+-------------+-------------+-------------+-------------+---------------+

3.4. Çağrı Durum Makinesi (CSTS):

Mesaj Tipi (Msg Type) CSTS Durumu SIP Eşdeğeri İşlev Açıklaması
0x01 (IAM) Initial Address Message INVITE Yeni çağrı başlatma isteği, arayan ve aranan numara bilgisi.
0x06 (ACM) Address Complete Message 180 Ringing Hedef telefonun çaldığını bildiren geri bildirim sinyali.
0x09 (ANC) Answer Charge / Connect 200 OK Hedef telefonun açıldığını ve konuşmanın başladığını bildirir.
0x0C (REL) Release Message BYE / CANCEL Çağrıyı sonlandırma isteği.
0x10 (RLC) Release Complete 200 OK (BYE) Devrenin boşaltıldığını ve yeni çağrıya hazır olduğunu onaylar.
